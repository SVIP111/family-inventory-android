# 安卓客户端设计说明（family-inventory）

## 1. 设计目标

后端 `family-inventory` 是一个 Go 静态服务：内嵌 HTML/JS 前端 + JSON 文件存储 + 内存令牌会话。
安卓端要做到「兼容」，意味着：

1. **零服务端改动**：只调用 `main.go` 里已注册的 `/api` 路由；
2. **同数据同语义**：字段名、状态码、错误文案、筛选规则（位置子树递归、标签不分大小写、搜索覆盖路径与条码）与网页端一致；
3. **能共存**：手机与网页同时操作同一份 `data.json`，不需要同步或迁移。

## 2. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| UI | Kotlin + Jetpack Compose（Material 3） | 原生声明式 UI，和网页端的卡片/弹窗结构容易对齐 |
| 网络 | OkHttp 4.12 | multipart 表单（图片、CSV）稳，超时可控 |
| 序列化 | kotlinx.serialization | `@Serializable` 数据类与 `store.go` 结构体逐字段对齐，`ignoreUnknownKeys` 兼容后端未来加字段 |
| 图片 | Coil 2.6 | 直接加载 `/uploads/...` 与 `/api/qr?text=...`（两者都是公开资源，无需带请求头） |
| 扫码 | CameraX + ZXing core | 无需 Google 服务，离线可用；一维码/二维码通吃 |
| 状态 | ViewModel + `mutableStateOf` | 单 Activity、页面用 sealed `Screen` 表示，避免额外导航依赖 |

包结构：`data/`（模型、API、配置持久化）与 `ui/`（状态、主题、各页面）分离，
`MainViewModel` 是唯一的数据入口，页面只做渲染和事件转发。

## 3. 接口对照表

基址来自用户在登录页填写的服务器地址（`http://host:port`，末尾不带斜杠）。

| 页面 / 动作 | 方法 & 路径 | 请求要点 | 响应 |
|---|---|---|---|
| 启动检查 / 检测服务器 | `GET /api/auth/status` | 无令牌也可 | `{registered, authenticated}` |
| 首次注册 | `POST /api/auth/register` | JSON `{username,password,confirm}` | 201 `{token,username}`；409 已有账号 |
| 登录 | `POST /api/auth/login` | JSON `{username,password}` | 200 `{token,username}`；401 用户名或密码错误 |
| 退出 | `POST /api/auth/logout` | Bearer | `{ok:true}` |
| 顶部统计 | `GET /api/stats` | Bearer | `{items,locations,withImage}` |
| 位置列表 / 树 | `GET /api/locations` | Bearer | `[{id,parentId,name,imageFile,createdAt}]` |
| 新建位置 | `POST /api/locations` | JSON `{name,parentId}` | 201 Location；409 同级重名 |
| 删除位置 | `DELETE /api/locations/{id}` | Bearer | 有物品/子位置时 409 |
| 上传位置布局图 | `POST /api/locations/{id}/image` | multipart 字段 `image` | 200 Location |
| 标签 | `GET /api/tags` | Bearer | `["数码","备用",…]` |
| 仪表盘汇总 | `GET /api/summary` | Bearer | `{byLocation:[{name,count,quantity}],byTag:[…],topItems:[{id,name,quantity,location}]}` |
| 标签改名 | `PUT /api/tags/rename` | JSON `{old,new}` | 200 `{ok,tags}`；404 标签不存在；400 新名为空 |
| 物品列表 | `GET /api/items?location=&tag=&q=` | 位置传 **ID**（子树递归）；tag 精确匹配；q 覆盖名称/描述/路径/条码/标签 | `[Item]`，按 `updatedAt` 倒序 |
| 物品详情 | `GET /api/items/{id}` | Bearer | Item；404 |
| 新增物品 | `POST /api/items` | multipart：`name,description,locationId,locationName,barcode,tags,quantity,image` | 201 Item |
| 编辑物品 | `PUT /api/items/{id}` | 同上；**不传 image 时后端保留原图** | 200 Item |
| 删除物品 | `DELETE /api/items/{id}` | Bearer | `{deleted:true}` |
| CSV 导入 | `POST /api/items/import` | multipart 字段 `file`（UTF-8 CSV） | `{added,failed,errors:[{row,name,reason}]}` |
| 二维码图片 | `GET /api/qr?text=<urlencoded>` | 公开 | `image/png`（256×256） |
| 物品/位置图片 | `GET /uploads/{file}` | 公开 | 原始图片 |

### 二维码内容约定

与网页端完全相同，扫码后打开网页详情页：

- 物品：`<base>/?item=<id>`
- 位置：`<base>/?loc=<id>`

## 4. 关键实现细节

### 4.1 位置选择与「自动建层级」

后端 `resolveLocationLocked` 的规则是：给 `locationId` 就按 ID 解析；只给 `locationName` 时，
先按完整路径匹配、再按根级名称匹配，最后按 `/` 逐级查找或创建。

安卓端的处理：
- 从位置树弹窗选择 → 传 `locationId`，名称只作展示（`locationName` 同时带上完整路径，便于后端兜底）；
- 手动输入「主卧 / 衣柜」这种新路径 → `locationId` 置空，交由后端自动逐级创建。

筛选时统一传位置 **ID**，这样选中「主卧」会包含「衣柜」「第一层」等子位置的物品，
和网页端「含子位置」的提示一致。

### 4.2 表单提交

`POST/PUT /api/items` 一律用 `multipart/form-data`（后端 `parseItemForm` 走 `ParseMultipartForm`），
即便不带图片也发 multipart，避免后端走到 JSON 解析分支：

```
name=… description=… locationId=… locationName=… barcode=… tags=… quantity=… [image=@file]
```

`quantity` 后端会把 `<=0` 归为 1；标签由后端 `normalizeTags` 统一按 `,，、;；空白` 切分去重，
所以客户端只传原始字符串（中文逗号会被正常拆分）。

### 4.3 鉴权与过期

- `Authorization: Bearer <token>`，令牌存 SharedPreferences；
- 任意接口返回 401 → `UnauthorizedException` → 清本地令牌、跳登录页并提示「登录已过期」；
- 服务器地址变更 → 主动清令牌（旧令牌对新服务器无意义）。

### 4.4 扫码

`ImageAnalysis` 取 YUV_420_888 首平面，处理 `rowStride` 填充后构造 `PlanarYUVLuminanceSource`；
先按原方向解码，失败则旋转 90° 再试（竖屏取景时条码通常是横向像素排列），
用 `AtomicBoolean` 保证只回调一次，`STRATEGY_KEEP_ONLY_LATEST` 控制帧堆积。

### 4.5 明文 HTTP

家庭内网 NAS 部署基本是 `http://`，所以 manifest 同时设置 `usesCleartextTraffic` 与
`network_security_config.xml` 允许明文；如果将来上公网 HTTPS，建议把该配置改成仅允许特定域名。

## 6. 1.0.1 → 1.0.2 修复：扫码闪退

现象：点「扫码」按钮立即闪退。

原因与改动：

1. **相机权限申请位置**：原实现在扫码 `Dialog` 内部用 `rememberLauncherForActivityResult` 注册并 `launch` 权限请求。
   Dialog 是独立窗口的子组合，在部分机型上该注册/启动链路不稳定，改为**在页面层（ItemsScreen / EditScreen）申请**，
   授权回调后再打开扫码弹窗（`rememberCameraGate`）。
2. **相机生命周期绑定**：原来在弹窗内取 `LocalLifecycleOwner`，拿到的是弹窗窗口的生命周期，
   Compose Dialog 的 ViewTree 上不一定有 LifecycleOwner，CameraX `bindToLifecycle` 会抛异常。
   改为由页面把 **Activity 级 LifecycleOwner** 作为参数传入，相机跟随页面生命周期。
3. **相机初始化兜底**：`ProcessCameraProvider.getInstance(...).get()`、`bindToLifecycle`、分析器回调全部包在
   `runCatching` 里，失败时弹窗内显示「相机启动失败：…」并通过 Snackbar 提示，不再抛出未捕获异常。
4. **解码线程安全**：识别结果用 `AtomicBoolean.compareAndSet` 保证只回调一次；`ImageProxy` 在 `finally` 中关闭；
   页面销毁时先 `unbindAll()` 再 `shutdown()` 执行器。
5. **崩溃自诊断**：新增 `CrashReporter`（`App` 中安装默认异常处理器），把堆栈写到 `filesDir/last_crash.txt`；
   下次启动读取并弹窗展示，可一键复制，便于没有 logcat 时定位真机问题。

### 1.0.2：真机堆栈确认的根因

1.0.1 装机后仍闪退，自诊断拿到了堆栈：

```
java.lang.IllegalStateException: CompositionLocal LocalLifecycleOwner not present
  at androidx.lifecycle.compose.LocalLifecycleOwnerKt$LocalLifecycleOwner$1.invoke(LocalLifecycleOwner.kt:26)
  at com.family.inventory.ui.ItemsScreenKt.ItemsScreen(ItemsScreen.kt:611)
```

原因：`androidx.lifecycle:lifecycle-runtime-compose:2.8.0` 里的
`androidx.lifecycle.compose.LocalLifecycleOwner` 是个 `compositionLocalOf { error(...) }`，
必须由上层提供；本工程用的是 Compose UI 1.6.8 + activity-compose 1.9，这套组合没有提供该局部变量，
所以只要读取 `.current` 就抛异常（点击扫码 → `showScan=true` → 重组时读取 → 闪退）。

修复：不再使用任何 CompositionLocal 取生命周期，改为 `currentLifecycleOwner()`
沿 `LocalContext` 的 Context 链找到承载页面的 `ComponentActivity`（`ContextWrapper` 递归），
把它作为参数传给 CameraX。Activity 版 Compose 的 `LocalContext` 就是该 Activity，稳定可得。

> 之后如再需要 `LocalLifecycleOwner`，请改用 `androidx.compose.ui.platform.LocalLifecycleOwner`
> 或直接从 Activity 取，避免再次踩这个坑。

> 说明：1.0.1 的扫码弹窗在无相机硬件/无权限的环境下会走到「相机启动失败」提示分支，不会崩溃。

## 7. 1.0.3：物品图片支持直接拍照

- **入口**：编辑/新增物品页的「物品图片」一栏，除「从相册选择」外增加「拍照」（无相机硬件则隐藏）。
- **实现**：`FileProvider`（authority `com.family.inventory.fileprovider`，只暴露 `cache/photos/`）
  把临时文件转成 `content://` 交给系统相机（`ACTION_IMAGE_CAPTURE` + `EXTRA_OUTPUT`），
  自定义 `TakePhotoContract` 显式加 `FLAG_GRANT_READ/WRITE_URI_PERMISSION`，
  并对能响应拍照的应用逐个 `grantUriPermission`，兼容国产 ROM 相机。
- **权限**：manifest 声明了 `CAMERA`，按 Android 规则调系统相机也需该权限已授予，
  因此复用页面层的 `rememberCameraGate`，未授权时先申请。
- **体积**：相机原图常 5–15MB，超过后端 10MB 上限；拍照后用 `inSampleSize` 采样到最长边 ≤1600px，
  JPEG 质量 85 起逐步降到 45，直到 ≤10MB，再作为 `image` 字段上传（mime `image/jpeg`）。
- **预览**：压缩后的字节用于上传，预览直接用 `content://` 临时 URI 交给 Coil。

## 9. 1.0.5：扫码分发与返回键

- 现象一：批量模式下按系统返回键无法退出批量（顶栏/底栏都被批量栏替换，只剩「退出批量」一个出口）。
  修法：`MainActivity` 的 `BackHandler` 补一条规则——当前页是物品列表且处于批量模式时，返回键调用 `toggleSelectMode()`；其余子页面仍回列表。
- 现象二：扫码后只把整条文本塞进搜索框，扫自家物品二维码（`<base>/?item=<id>`）时整条 URL 变成关键词，自然搜不到；
  扫码入口看起来"只能返回链接"。
  修法：新增 `MainViewModel.handleScanResult()`，本地解析扫码文本（`java.net.URI` 取 query + `URLDecoder` 解码），
  **不改服务端**：
  - 命中 `item=<id>` → 列表里有就直接打开详情，没有就 `GET /api/items/{id}` 拉回来再打开；
  - 命中 `loc=<id>` → 用该位置做子树筛选并提示；
  - 其他情况（EAN/CODE128 商品条码、纯数字、任意文本）→ 作为关键词走 `GET /api/items?q=` 搜索。
  二维码内容格式沿用后端既有约定，故客户端独立实现即可，接口零改动。

## 11. 1.0.0（重编号）：版本信息展示

- 版本号按需求重置为 `1.0.0`，但 `versionCode` 保持单调递增（8），否则装过 1.0.6 的机器会因为「降级」拒绝安装。
